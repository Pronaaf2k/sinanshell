## Architecture

`tokenize` preserves quote context in `Word` objects and separates shell operators from literal arguments. `parse` validates the complete line before execution and produces conditional pipelines. `Word.expand` expands variables and filenames when a pipeline executes, so later commands see updated environment state and exit status.

`Shell.builtin` handles state belonging to the parent shell. `Shell.pipeline` applies expansion and redirection. `Shell.external` starts programs with argument lists through `subprocess.Popen`, connects pipes, waits for children, and handles launch failures. `Shell.run` reads commands. Prompt styling and optional readline integration are also in `Shell`.

## Implementation rules

- Keep all runtime shell code in `pith.py`. The assignment requires one source file; tests and documentation can remain separate.
- Keep Python 3.8 compatibility and a standard-library-only runtime. Do not add pip dependencies or require a native compiler.
- Launch programs directly with argument lists and `shell=False`. Do not forward the entire command line to Bash, `sh`, or `os.system` as the implementation.
- Keep directory and environment changes in the shell process. Reuse external programs instead of adding built-in copies of `ls`, `cat`, `echo`, or other ordinary utilities.
- Preserve quote context, literal operators, redirection order, conditional execution, and exit codes when changing the parser or executor.
- Close unused pipe ends and file handles. Reap every child, including when a later pipeline stage fails to launch. Keep the shell alive after ordinary input and command errors.
- Preserve the ASCII fallback, `NO_COLOR`, and operation without readline. Terminal fonts are chosen by the terminal, not installed or changed by the shell.
- Preserve UTF-8 text and LF line endings. Keep generated bytecode, `.qa/`, and local `sccs-work/` files out of Git.
- Update help text, the README, and relevant behavioral tests when supported syntax or behavior changes. Describe unsupported syntax plainly rather than implying full Bash or POSIX compatibility.

## Verification

Run from the project root on Linux:

```bash
python3 -m py_compile pith.py
python3 -m unittest discover -s tests -v
```

Optional equivalents are `make check`, `make test`, `make run`, and `make plain`. On Windows, use an available Python 3.8+ interpreter for the portable checks and report skipped Unix tests accurately.

The latest recorded run in the original Windows workspace had 43 passing tests and 4 skipped Unix-specific tests. Linux execution, readline interaction, and the SCCS workflow have not been verified on `cslinux.ucalgary.ca`. Do not claim they passed without actually running them.

The next verification priority is to run the full suite on Linux, then check the interactive terminal behavior: prompt layout, narrow windows, Tab completion, history recall, Ctrl+C at the prompt and during a command, Ctrl+D, and foreground terminal applications. Fix reproducible defects and add focused regression coverage. Keep these engineering checks separate from the student's personal dogfooding record.
